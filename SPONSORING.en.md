# Support Game Release Guard

Sponsorship helps maintain the five-engine security Skill, local Unity / Unreal release tools, documentation, tests and compatibility checks. **The core Skill, source code and normal security updates remain free under the [MIT LICENSE](LICENSE).** Sponsorship is not required to use existing open-source features, report problems or contribute.

They do not imply platform approval or active memberships. Real payment links and `.github/FUNDING.yml` will be added only after the maintainer confirms the public profiles.

### Patreon

Patreon is a first-rollout channel, displayed alongside the other three, for ongoing support and following development. **Public creator profile: awaiting the maintainer's confirmed link.** Template field: `patreon`; placeholder: `REPLACE_WITH_VERIFIED_PATREON_HANDLE`. These optional **monthly Patreon tiers in USD are drafts**, not published products or current membership benefits. This repository setup does not change an existing account, billing settings or member content.

## Optional tiers for the other channels

These are also **monthly suggestions in USD**, not active offers. Availability depends on the platform settings actually enabled. One-time support does not automatically purchase ongoing benefits.

| Suggested amount | Optional direction |
| --- | --- |
| **$3 / month** | Support project maintenance. |
| **$5 / month** | Monthly supporter acknowledgment, with names displayed only by consent. |
| **$15 / month** | Join project direction discussions; technical and scheduling decisions remain with the maintainer. |
| **$30 / month** | Developer exchange and occasional project progress updates, without dedicated support or delivery deadlines. |

No tier sells security guarantees, priority vulnerability fixes, unimplemented features or private game audits. Normal security updates stay freely available. Exchanges and updates must fit the maintainer's sustainable capacity; any actual benefits and billing cycle must be clear on the real platform page before payment.

Public acknowledgment is always optional and uses the supporter's agreed display name. Payment records, email addresses and legal identities are not published. Do not put banking details, tax forms, identity documents or transaction receipts in issues, pull requests or chats. Payments, renewals, cancellations and refunds follow the selected platform's actual process; this repository does not process payments.

<a id="activation"></a>
## Maintainer activation steps

1. **Handle accounts and payouts personally.** Follow [GitHub's enrollment guide](https://docs.github.com/en/sponsors/receiving-sponsorships-through-github-sponsors/setting-up-github-sponsors-for-your-personal-account), including eligibility, 2FA and required identity, bank and tax steps. Set up Ko-fi / Buy Me a Coffee and supported payout methods yourself. Use the existing Patreon account and personally review its page, payouts, plan and tier drafts. Submit required documents only to official services, with accurate country and identity information; never commit them or send them to an AI assistant.
2. **Provide real public links.** Check ownership, signed-out access and payment readiness. An existing account does not prove it can receive payments. Public URLs and handles are enough; no passwords, tokens or identity records are needed. Unavailable channels stay pending, and a subset can be enabled first.
3. **Create the live configuration.** Use [.github/FUNDING.example.yml](.github/FUNDING.example.yml) as the structure for `.github/FUNDING.yml` only after real handles are confirmed. Keep ready channels only; remove unconfigured entries and every `REPLACE_WITH_VERIFIED_…` placeholder. Use the native `patreon` field. Leave Open Collective commented out in the example. Never rename and commit the unchanged placeholder template.
4. **Update both languages.** Synchronize both READMEs and both sponsorship pages. Replace an information entry with a real public profile only for confirmed channels; leave the others pending. Keep fee and tier changes aligned across languages too.
5. **Confirm GitHub settings personally.** A repository administrator enables `Settings → General → Features → Sponsorships`. Review the live configuration in a PR before merging it into the default branch, `main`; no bank details belong here. The example file does not activate Sponsor. [Official Sponsor Button guide](https://docs.github.com/en/repositories/managing-your-repositorys-settings-and-features/customizing-your-repository/displaying-a-sponsor-button-in-your-repository)
6. **Check the public pages.** In a signed-out browser, follow the Sponsor menu and both READMEs to the correct profiles and check for leftover placeholders. Viewing pages does not require a payment, subscription or account change. The account holder decides when to activate charges and publish member content.

If only Patreon is ready, the live file should contain just the confirmed `patreon` entry; the other three remain pending on the homepage. GitHub's repository Sponsor menu does not itself approve a GitHub Sponsors receiving profile. External platforms handle their own payments.

If a link is wrong, remove that entry and the bilingual payment links through a new PR, keep the explanatory text, then verify the correct profile. Do not close accounts, cancel someone else's memberships or change billing plans on the owner's behalf.
